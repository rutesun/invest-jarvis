# Change Record: NH 국내·미국 계좌와 매매일지

**Status**: In Progress
**Date**: 2026-11-06
**PRs**: -
**Type**: feat

## Why

주 사용 증권사의 실제 보유와 Jarvis가 사용하는 수동 보유 설정 사이의 차이를 줄이고, 앱에서 거래한 사실을 투자 이유·계획·복기와 함께 관리한다.

## Changes

### Added

- 국내·미국 NH 잔고 조회와 실제 보유 기준 브리핑을 추가한다.
- 국내 누적 체결과 미국 일별 매매내역을 중복 없이 수집하는 로컬 거래 장부를 추가한다.
- 투자 건별 거래 흐름과 이유·무효화 조건·추가매수 조건·복기를 연결한다.
- 종목·기간·시장·복기 여부·태그 필터와 수동 전략 분리, 로컬 Markdown 내보내기를 제공한다.
- 실제 국내 잔고의 RP 등 주식 코드 미지원 자산을 별도 표시하고 주식 분석에서 제외한다. 원본 잔고와 합계는 유지한다.

### Changed

- 매매일지 목록·내보내기를 월별 거래금액과 투자 건별 상태 중심의 요약으로 바꾸고 `--detail`로 기존 전체 정보를 제공한다. 계좌·통화별 집계와 선택 투자 건의 전체 이력이라는 범위를 명시한다.
- 목록·상세·내보내기에 현재 NH 계좌 전체 보유와 조회 시각을 별도 표로 연결한다. 장부 잔여를 덮어쓰거나 과거 투자 건에 현재 수량을 배정하지 않는다. `--no-balance`로 로컬 장부만 조회할 수 있다.
- NH 연결 후 일반 브리프도 매번 잔고 조회→playbook 보유 갱신→분석 순으로 실행한다. 계좌 연결을 기억하며 손절·메모·관심 목록·주석을 보존한다. 전량 매도 종목의 사용자 설정은 재진입 시 복원하고, 소수점 수량도 파일 재로드에서 보존한다.
- playbook 원문을 백업하고 잠금·파일 변경 검사를 거쳐 원자적으로 저장한다. 삭제한 사용자 설정을 되살리지 않으며, YAML alias/merge가 있으면 원본을 보존하고 자동 저장을 중단한다.
- 거래 수집 사용 예시를 3개월로 변경한다. 수집 시작·종료일은 계속 명시한다.

### Fixed

- 브리프의 종목 제목 아래 분석 제목을 중첩하고, 후속 참고 정보를 별도 항목으로 구분한다. 코드 블록은 보존한다.
- NH 과거 조회의 정상 연속조회 코드 `00218`을 조건부 허용한다. 잘못된 페이지·cursor 방어는 유지한다.

## Impact

계좌 연결 전의 YAML 브리프는 기존 동작을 유지한다. NH 연결 후에는 일반 brief도 저장된 계좌를 조회하고 playbook을 갱신하며 `--broker local`로 로컬 동작을 선택할 수 있다. 기존 파일은 private 경로에 백업 후 원자적으로 교체한다. 키 이름은 NS_APP_KEY와 NS_APP_SECRET이다. 개인 거래 장부는 git에서 제외된 data/broker에 저장한다.

## Constraints

주문 전송·주문 가능 금액 기반 매수 수량 제한·Notion 자동 전송은 포함하지 않는다. 공식 예제 fixture 검증과 실제 계좌 연결 검증을 구분한다. 미국 거래 반영 지연과 날짜 단위 기록의 묶음 한계를 표시한다.

## Validation

- playbook 자동 갱신 후 관련 테스트 476개와 변경 Python 파일 Ruff를 통과했다. 계좌 자동 재사용·사용자 설정/주석·매도 후 재진입·삭제 의도·소수점 재로드·원자적 저장 실패·동시 저장·alias/merge 거부를 검증했다.
- 기본 전체 회귀는 3,623 passed, 1 skipped, 15 deselected였다. 후속 보강은 관련 476개로 별도 재검증했다. 기존 Pydantic/pandas 경고 2개가 있다. 기술 분석 통합 경로까지 확장한 추가 실행도 514개를 통과했으며 마지막 YAML 참조 판정 보강은 관련 476개에서 재검증했다.
- 공개 NH 예제와 합성 paging/장애 응답을 사용해 provider→SQLite→CLI 경로, 소수점·메모·수동 경계 보존을 검증한다. 개인 raw 응답은 fixture에 포함하지 않는다.
- 실계좌 인증·계좌·국내/미국 잔고, 3개월 거래 동기화·중복 방지·요약/상세 Markdown 내보내기와 실제 시세를 사용하는 `brief --broker nh --no-llm` 실행을 확인했다. 최종 브리핑은 종료코드 0, 종목 조회 실패 0이었다. 이후 제목 계층 수정은 기존 브리프 산출물에 적용하고 본문·수치 보존을 검증했다. LLM 문장 생성은 실행하지 않았다.
- 최초 브리핑에서 KIS HTTP 500을 관찰했으나 최종 재실행에서는 발생하지 않았다. 기존 기술분석의 거래량 나눗셈 경고 4건이 있었고 최종 리포트에는 NaN/inf 값이 없었다.
- 실제 미국 거래의 모든 표기 변형이나 같은 날 정확한 체결 순서를 검증한 것으로 해석하지 않는다. 제공된 거래 전후잔고와 장부가 맞지 않으면 불완전 이력을 표시한다.
- 공개 잔고 fixture→Provider→일지 CLI의 현재 수량·조회 시각과 불완전 이력 분리를 검증했다. 현재 잔고를 포함한 실계좌 Markdown 내보내기도 실행했으며 기존 거래 건수·불완전 표시는 유지됐다.
- 실제 NH 잔고로 worktree playbook 갱신·원문 백업·사용자 설정 보존을 확인했다. 추가로 일반 brief의 실제 계좌 재조회와 파일 저장을 검증했다. 이 추가 실행의 분석 단계는 probe로 대체했으며 전체 분석 검증과 구분한다.
