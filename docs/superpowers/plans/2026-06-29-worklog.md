# Worklog (작업 일지) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 작업 중의 결정·버그수정·마찰·방향전환을 `docs/worklog/<topic>.md`에 시간순으로 기록하는 `work-log` 프로세스 스킬과 운영 규칙을 추가한다.

**Architecture:** 에이전트가 체크포인트에서 `work-log` 스킬을 호출해 정해진 템플릿으로 엔트리를 append한다. 트리거는 CLAUDE.md/AGENTS.md 규칙으로 명시(훅 아님). worklog는 change-record/ADR의 1차 재료이며 git에 커밋한다.

**Tech Stack:** Markdown 문서, Claude Code Skill(`.claude/skills/`), Codex Skill(`.agents/skills/`). 코드 변경 없음 — 검증은 파일 존재·포맷 확인과 dogfooding.

## Global Constraints

- 응답·문서 본문은 한글(코드·주석·변수명 제외). 출처: `CLAUDE.md`.
- 스킬 위치: Claude는 `.claude/skills/`, Codex는 `.agents/skills/` (기존 `jarvis-*` 스킬과 동일 배치).
- 공통 규칙은 `CLAUDE.md`와 `AGENTS.md` 양쪽에 동일 반영. 출처: `CLAUDE.md`/`AGENTS.md` Collaboration Rules.
- 문서 규칙 변경의 기준 문서는 `docs/DOCUMENTATION.md`.
- worklog 파일명은 주제(topic) kebab-case. 브랜치명을 파일명으로 쓰지 않는다.
- 엔트리 타입은 정확히 4종: `Decision`, `Bug`, `Friction`, `Pivot`.
- 강제 훅은 도입하지 않는다(`DOCUMENTATION.md §7` 철학).

# Work Log

작업 중의 결정·버그수정·마찰·방향전환을 `docs/worklog/<topic>.md`에 시간순으로 기록한다.
change-record/ADR의 1차 재료다. 엔트리 포맷의 기준은 `docs/worklog/_templates/worklog.md`.

## 언제 호출하나 (트리거)

- 설계 결정이 확정된 직후 → `decision`
- 버그 수정이 검증된 후 → `bug`
- 도구 부재로 막히거나 맥락을 잘못 잡았을 때 → `friction`
- 접근을 폐기·전환할 때 → `pivot`

## 절차

1. 날짜·시간과 브랜치를 구한다:
   - `date '+%Y-%m-%d %H:%M'`
   - `git rev-parse --abbrev-ref HEAD`
2. 대상 파일 `docs/worklog/<topic>.md`를 정한다. `<topic>`은 작업 주제 kebab-case
   (브랜치명을 그대로 쓰지 않는다). 같은 작업의 후속 엔트리는 같은 파일에 append한다.
3. 파일이 없으면 `docs/worklog/_templates/worklog.md`의 헤더 블록으로 새로 만든다
   (`Branch`/`Started`/`Status`/`Links` 채움).
4. 인자 `type`에 맞는 엔트리 블록을 파일 끝에 append한다 (아래 포맷).
5. 최근 대화 맥락에서 각 필드를 채운다. **맥락에 근거 없는 내용은 지어내지 않고
   `{확인 필요}`로 표시**한다.
6. 작성 후 한 줄로 무엇을 어디에 기록했는지 보고한다.
