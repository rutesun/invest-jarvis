# jarvis brief — 일일 포트 액션 종합 설계 스펙

- **작성일**: 2026-07-14
- **상태**: Draft v1 (브레인스토밍 승인 반영)
- **대상**: 로컬 YAML 보유·워치리스트 기반 일일 액션 브리핑 CLI (`jarvis brief`)
- **배경**: 2026-07-02 요구사항 인터뷰에서 확정한 1차 타깃. 로드맵 — 1차 `jarvis brief` → 2차 의사결정 피드백 루프 → 3차 발굴 엔진 강화

## 1. 배경 및 목표

사용자 페인: "정보는 많은데 **내 보유/관심 종목 기준으로 오늘 뭐할지**로 좁혀지지 않는다."

기존 도구의 간극:
- `portfolio` 명령은 KIS 실시간 잔고 전제 — 해당 계좌에 잔고가 없어 시작점부터 사용 불가
- `report ticker`는 관찰 리포트 — 보유(평단·수량) 개념과 액션 판정이 없음
- 미국 보유분은 `playbook.yaml`에만 존재하고 어떤 일일 뷰에도 연결 안 됨

**목표 (인터뷰 Restate 게이트 승인 원문)**: 기존 `report daily-v2`와 독립된 신규 온디맨드 CLI `jarvis brief`를 만들어, 로컬 YAML로 관리하는 보유(평단·수량)와 워치리스트(KR·US)를 입력받아 ①오늘 주목할 Top-N 우선순위 큐 + ②종목별 액션 신호(hold/추가/축소/청산 + 기술점수·레벨·뉴스/공시·수급 근거) + ③진입 임박 후보 연결을 마크다운으로 출력하고, "아침에 열면 손댈 1–3종목과 근거가 즉시 보이고 놓칠 상황(스탑 근접·급변·진입 임박)을 먼저 짚어준다"를 만족시킨다.

**핵심 원칙**: **사실은 코드가, 해석은 LLM이** (Playbook 스펙과 동일 원칙). 액션·순위·근거는 규칙이 결정적으로 확정하고, LLM은 확정된 사실의 문장화만 담당한다.

**수용 기준 (인터뷰 확정)**:
1. 즉시 액션 가능 — 아침에 열면 오늘 손댈 종목 1–3개 + 근거가 바로 보인다
2. 근거가 명확해 신뢰 — 각 액션 신호에 근거(점수·레벨·뉴스·수급)가 달려 그대로 믿고 실행할 수 있다
3. 놓칠 것을 먼저 짚어줌 — 스탑 근접·급변·진입 임박을 브리핑 상단에 올려준다

## 2. 범위

### 포함
- `BriefPipeline` 신규 (`src/pipelines/brief.py`) + CLI `jarvis brief`
- `playbook.yaml`에 `watchlist` 섹션 추가 + `load_holdings` 로더 확장
- 종목별 액션 판정: 보유 → `evaluate_exit` 재사용 / 워치 → PlaybookEngine gate 재사용
- 규칙 기반 우선순위 점수(주목도) + 전 종목 정렬 + Top-3 하이라이트
- LLM 배치 1콜 문장화 (실패 시 규칙 원문 fallback)
- 마크다운 출력 (`reports/YYYY-MM/brief_YYYY-MM-DD.md`) + 터미널 rich 출력
- **PortfolioPipeline 제거** (별도 커밋): 파이프라인 + `jarvis portfolio` CLI + PortfolioTool + 관련 테스트·문서. KIS provider `get_balance()`는 보존

### 제외 (인터뷰에서 명시적으로 비목표 확정)
- `report daily-v2` 등 기존 리포트 파이프라인 변경
- 포트 전체 리스크/노출 뷰 (섹터 집중도·현금비중 등)
- 신규 발굴 엔진 (3차 로드맵) — 이번엔 워치리스트 내 "진입 임박 후보" 표면화까지만
- Notion 업로드 / 스케줄 자동 실행 / 텔레그램 푸시
- KIS 실시간 잔고 연동
- 의사결정 피드백 루프·백테스팅 (2차 로드맵)

## 3. 아키텍처 / 데이터 흐름

레이어드 아키텍처(Providers → Tools → Pipelines → CLI) 준수. 기존 파이프라인 무변경.

```text
playbook.yaml ──┐
                ├─→ BriefPipeline.run()
MacroTool ──────┘        │
                         ├─ 1. 매크로 스냅샷 1회 (VIX·F&G·금리·달러)
                         ├─ 2. 종목 루프 (holdings + watchlist 전체, 누락 없음)
                         │     ├─ TechnicalAnalysisTool (기술점수·지표)
                         │     ├─ 보유 종목 → evaluate_exit  → hold/reduce/liquidate + 신호
                         │     ├─ 워치 종목 → PlaybookEngine gate → 적격/임박/거부 + 근접도
                         │     └─ NewsTool(3건) + 한국주식이면 InvestorFlow(수급)
                         ├─ 3. 규칙 랭킹 → 우선순위 큐 (전 종목 정렬, Top-3 하이라이트)
                         ├─ 4. LLM 배치 1콜 → 종목별 슬롯 서술 (사실은 규칙 결과만 사용)
                         └─ 5. 출력: 터미널(rich) + reports/YYYY-MM/brief_YYYY-MM-DD.md
```

설계 결정 (인터뷰·브레인스토밍 확정):
- **전 종목 풀 평가** — 워치리스트 전 종목이 브리핑에 빠짐없이 포함. 사전 필터로 종목을 탈락시키지 않음 (우선순위는 정렬로만 표현). 실행시간은 부차 요건
- **LLM은 배치 1콜** — 종목당 호출 아님. 규칙이 확정한 구조화 결과 전체를 한 번에 전달
- 시장지수 이력은 시장(KR/US)당 1회 fetch 후 재사용, KIS 호출은 기존 규칙대로 순차 처리

## 4. playbook.yaml 스키마 확장

기존 구조 유지, `watchlist` 섹션만 추가:

```yaml
account:            # 기존 그대로
  krw: { capital: ..., risk_per_trade_pct: ... }
  usd: { capital: ..., risk_per_trade_pct: ... }

holdings:           # 기존 그대로 (보유 = 평단·수량 필수)
  - ticker: "005930"
    quantity: 10
    avg_price: 72000
    stop_price: 65000      # 선택

watchlist:          # 신규 (관심 = 티커만 필수)
  - ticker: NVDA
    note: "AI 반도체 대장"   # 선택, 브리핑에 그대로 표기
  - ticker: "035420"
```

- 같은 티커가 holdings·watchlist 양쪽에 있으면 **보유 우선** (경고 로그 후 워치에서 무시)
- 로더는 기존 `load_holdings()` 확장 — `HoldingsConfig`에 `watchlist: list[WatchEntry]` 필드 추가
- 저장소 선택 근거: SSoT 단일 파일 유지, 기존 로더 재사용, `analyze`의 playbook 연동과 자동 일치. DB는 2차(피드백 루프)에서 시계열 이력이 필요해질 때 도입

## 5. 액션 판정 · 랭킹 규칙

### 5.1 액션 판정 (기존 부품 출력 그대로 사용)

| 구분 | 판정 소스 | 결과 |
|---|---|---|
| 보유 | `evaluate_exit` (exit_rules.py) | `청산` / `비중축소` / `보유` + 신호 목록 + 평단 대비 R값 |
| 보유 보조 | `stop_price` 설정 시 | 현재가가 스탑 대비 **3% 이내**면 `스탑 근접` 경고 |
| 워치 | PlaybookEngine gate | `매수 적격`(통과, 사이징 포함) / `진입 임박` / `거부` |
| 임박 기준 | gate 미통과지만 | Stage2 7조건 중 **5개 이상 충족** → 임박 (미충족 조건 라벨을 근거로 표기) |

### 5.2 우선순위 점수 (주목도)

결정적 계산. 높을수록 상단. 값은 초기값이며 운영하며 조정 가능한 상수로 관리.

```text
청산 신호        100   ← "놓치면 손실" 최우선
매수 적격 (워치)   90   ← "놓치면 기회"
비중축소          80
진입 임박 (워치)   60
보유 (약신호 있음) 30
거부 (워치)       20
보유 (이상 없음)   10

가산:
스탑 근접        +30
급변 보정        +20   (당일 등락 ±5% 이상)
```

- 뉴스는 **점수에 반영하지 않고 근거로 표기만** — 감성 점수화는 노이즈가 커서 제목 나열이 더 정직함
- 전 종목이 점수순 정렬되어 출력 (누락 없음), 상위 3개만 "오늘의 액션" 하이라이트
- 랭킹 로직은 순수 함수로 분리 (`src/tools/brief/scoring.py`) — I/O 없이 단위테스트 가능

## 6. LLM 배치 + 출력 포맷

### 6.1 LLM 배치

- 전 종목의 규칙 결과(액션·점수·신호·뉴스 제목·수급)를 구조화 JSON으로 **1콜**에 전달
- 종목별 서술을 Pydantic 구조화 출력으로 수신 (기존 `src/llm/` 패턴 재사용)
- LLM은 자유 문장이 아니라 **미리 정의된 슬롯**(기술적 근거/수급/뉴스 해석/다음 확인 지점)에 각 1–2문장을 채움
- **LLM 실패/타임아웃 시 슬롯별로 규칙 원문이 그대로 대체** — 브리핑은 항상 완성됨

### 6.2 종목별 불렛 구조 (사용자 확정: 구조화 불렛 출력)

슬롯은 보유/워치 각각 고정 세트. 데이터 없는 슬롯(예: 미국 종목의 수급)은 항목 자체를 생략.

```markdown
# Daily Brief — 2026-07-14

## 시장 환경
VIX 14.2 · Fear&Greed 62(Greed) · 10Y 4.1% — 한 줄 요약

## ⚡ 오늘의 액션 (Top 3)
1. [축소] 005930 삼성전자 (점수 80)
2. [적격] NVDA (점수 90)
3. [임박] 035420 (점수 60+20, 급변 보정)

## 보유 (3종목)

### 005930 삼성전자 — 비중축소 (R=1.8)
- **판정 근거**: 중신호 1개(종가 71,200 < SMA50 72,800)
- **가격/기술**: 현재가 71,200 (평단 대비 -1.1%) · RSI 48 · 추세 중립
- **수급(KR)**: 외국인 5일 순매도 3일, 기관 중립
- **뉴스**: "삼성전자 파운드리 수주 지연" (7/13) · 그 외 2건
- **스탑 상태**: 스탑 65,000 대비 +9.5% (근접 아님)
- **다음 확인 지점**: SMA50(72,800) 재돌파 여부

## 워치리스트 (5종목)

### NVDA — 매수 적격 (grade A)
- **판정 근거**: Stage2 7/7 충족 · RS 강세 · 섹터 강도 상위
- **가격/기술**: 현재가 165.2 · VCP 브레이크아웃 확인
- **사이징**: 12주 @ 165.2, stop 152.0 (리스크 1%)
- **수급/섹터**: 반도체 섹터 랭킹 2위
- **뉴스**: "NVDA 신규 수주 발표" (7/12)
- **다음 확인 지점**: 진입 후 stop 관리
```

## 7. 에러 처리

원칙: **개별 종목·데이터소스 실패가 전체 브리핑을 막지 않는다** (deep_dive의 graceful degradation 패턴 재사용).

| 실패 지점 | 처리 |
|---|---|
| 특정 종목 기술분석 실패 (yfinance/KIS 오류) | 해당 종목 "데이터 조회 실패" 항목으로 표시, 나머지 정상 진행 |
| PlaybookEngine 일부 실패 (섹터강도 등) | 기존 engine의 graceful None 그대로 — 해당 근거만 생략, 가능한 신호로 판정 계속 |
| 뉴스/수급 조회 실패 | 해당 슬롯 생략, 판정에 영향 없음 (둘 다 근거 표기용) |
| LLM 배치 콜 실패/타임아웃 | 전체를 규칙 결과 원문으로 대체 — 브리핑 자체는 항상 완성 |
| playbook.yaml 파싱 실패 (스키마 오류) | 즉시 예외로 중단 + 잘못된 필드 명시 (침묵 실패 금지) |
| watchlist·holdings 모두 빈 경우 | "설정된 종목 없음" 안내 후 정상 종료 (에러 아님) |

로깅: 종목별 실패는 `logger.warning`, 스키마 오류는 즉시 예외 — CLAUDE.md 테스트 원칙("가정이 벗어나면 조용히 내려보내지 않는다")과 일치.

## 8. 테스트 전략

이 기능은 **외부 API 신규 호출이 없다** — 기존 TechnicalAnalysisTool·PlaybookEngine·MacroTool·NewsTool·InvestorFlow 재사용이므로 골든 테스트 대상은 각 하위 도구 쪽에 이미 존재. brief 신규 테스트는:

1. **랭킹/판정 로직 단위테스트** (`src/tools/brief/scoring.py` 순수 함수)
   - 입력: `ExitVerdict`/`GateResult` 목 객체 조합
   - 검증: 점수표 정렬, 스탑 근접·급변 가산, holdings/watchlist 중복 시 보유 우선
2. **로더 확장 테스트** (`load_holdings`의 watchlist 파싱)
   - watchlist 있음/없음/중복 티커/note 누락 케이스 — 경계 계약 성격, 스키마 가정이 깨지면 즉시 실패
3. **BriefPipeline 통합테스트** — 전 도구 목 교체, 파이프라인 조립(순서·에러 격리)만 검증. golden fixture 중복 생성 안 함
4. **LLM fallback 테스트** — LLM 클라이언트 실패 목 처리 후 규칙 원문으로 브리핑 완성 검증

## 9. 결정 이력 (인터뷰 → 브레인스토밍)

| # | 결정 | 근거 |
|---|---|---|
| D1 | 1차 타깃 = 포트 액션 종합 (2차 피드백 루프, 3차 발굴) | 사용자 우선순위 "3→1→2". 매일 즉시 사용 가능, 토대 비용 최저 |

| D4 | 하이브리드 LLM: 규칙이 검증, LLM은 배치 1콜 문장화 | 사용자 제안. 근거는 결정적, 서술은 읽기 좋게 |

| D6 | 종목별 출력 = 구조화 불렛 (자유 문단 아님) | 사용자 확정. 슬롯별 근거 가시성 + LLM fallback 용이 |
