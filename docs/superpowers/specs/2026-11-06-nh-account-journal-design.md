# NH 국내·미국 계좌와 매매일지 설계

- 날짜: 2026-11-06
- 상태: 사용자가 잔고·브리핑·매매일지 및 국내·미국 범위를 승인함

## 목적과 사용자 흐름

주 사용 증권사 NH의 실제 보유를 Jarvis 브리핑에 연결한다. 앱에서 거래한 사실을 중복 없이 수집하고 투자 건별로 묶어, 사용자가 매매 이유·계획·복기를 남길 수 있게 한다.

1. `jarvis broker accounts`로 연결 가능한 계좌의 마스킹된 목록을 확인한다.
2. `jarvis broker holdings --account <계좌 식별자>`로 국내·미국 잔고를 조회한다.
3. `jarvis brief --broker nh --account <계좌 식별자> --no-llm`으로 실제 보유 기준 브리핑을 받는다.
4. `jarvis trades sync --account <계좌 식별자> --from YYYY-MM-DD --to YYYY-MM-DD`로 거래를 수집한다.
5. `jarvis trades list`, `jarvis trades show <투자건 ID>`, `jarvis trades note <투자건 ID>`로 기록을 확인하고 이유·무효화 조건·추가매수 조건·복기를 남긴다.
6. `jarvis trades split <거래 ID>`로 동시에 운용한 전략을 수동 분리한다. export는 로컬 Markdown이다.

명령 이름은 아래 구현 계획의 계약이다. 토큰 발급과 증권사 조회만 제공하며 주문 전송은 구현하지 않는다.

## 책임 경계

- NH: 실제 잔고·평가손익·체결/거래 사실. 키와 계좌 원문은 로그·오류·fixture에 남기지 않는다.
- 기존 KIS/yfinance: 차트와 기술 분석. NH 연동 때문에 시세 provider를 교체하지 않는다.
- Strategy: 기존 차트 판단을 유지한다. 계좌·손익·매매일지를 입력으로 읽지 않는다.
- PositionPlanner: 기존 실제 보유 기반 대응 수량 계산만 재사용한다. 주문 가능 금액 기반 수량 제한은 추가하지 않는다.
- playbook.yaml: 관심 종목·사용자 손절 기준·기존 risk 설정을 보존한다. NH 조회 결과로 원본 파일을 덮어쓰지 않는다.
- 매매일지: SQLite에 거래 사실과 사용자 메모를 분리해 저장한다. 점수 snapshot 저장과는 다른 거래 장부다. notebook 원본과 Notion은 자동 변경하지 않는다.

## 잔고와 브리핑

- 개인 실계좌만 기본 대상이며 모의·주문대리인 계좌는 자동 선택하지 않는다. 하나면 자동 선택, 여러 개면 마스킹 식별자로 명시 선택한다.
- 국내/미국 응답을 모두 끝까지 페이지 조회한 후 완성된 결과로 사용한다. 한 시장 실패를 빈 잔고로 바꾸거나 과거 YAML을 실제 잔고로 표시하지 않는다.
- 국내 현금/신용 등 원본 행 구분을 보존한다. 같은 종목의 브리핑용 합계는 수량 합산 및 가중 매입단가로 계산하되 구분별 상세를 볼 수 있어야 한다.
- 수량·금액은 Decimal로 해석한다. 소수점 수량은 표시·장부에 보존한다. 기존 정수 수량 planner에 전달할 때 잘라내지 않고 수량 계산 미지원 경고를 표시한다.
- KRW와 USD 손익·평가액을 구분한다. 동일 계좌의 국내·해외 총자산 필드는 범위 중복 가능성이 있어 단순 합산하지 않는다.
- 브리핑에는 NH 조회 시각과 보유 수량·평단·평가액·평가손익을 표시한다. NH 평가 가격과 차트 분석 가격은 출처·기준을 구분한다.
- 연결 계좌에서 사라진 종목은 보유로 남기지 않는다. 로컬 관심 종목·stop 설정은 종목 코드 정규화 후 재사용한다.

## 거래 장부와 투자 건

- 국내: 주문일자별 체결 조회의 `tot_cns_qty`와 체결평균단가를 사용한다. 주문수량/취소수량을 매매량으로 취급하지 않는다. 누적 부분 체결은 같은 account+market+date+order identity로 갱신한다.
- 미국: 일별거래내역 API의 거래일련번호를 기준으로 실제 매매 행만 수집한다. 소수점 거래를 포함하고 실거래일/조회 거래일을 구분한다. 결제 반영 지연 가능성을 화면에 표시한다. 미국 주문 조회와 동시에 같은 사실을 이중 장부화하지 않는다.
- 재수집은 중복을 만들지 않고 메모를 보존한다. 모든 페이지 수집 성공 후 한 번에 transaction으로 반영한다. 동기화 실패는 일부 기록을 완료로 표시하지 않는다.
- 투자 건은 계좌·시장·통화·종목별로 최초 매수부터 전량 청산까지 묶는다. 부분 매도는 같은 건에 남기고 재진입은 새 건이다.
- 과거 이력 없이 매도부터 시작하거나 보유 전량을 알 수 없는 경우 `이력 불완전`으로 표시한다. 자동 묶음은 거래 장부 기준이며 실계좌 완전 이력의 증명으로 표시하지 않는다.
- 같은 날 주문의 정확한 체결 시각을 모르면 임의로 정확한 시간순·전량 청산 후 재진입을 단정하지 않는다. 안정적인 표시순서와 묶음 제한을 설명한다.
- 수동 분리는 명시적 그룹 식별자를 보존하고 재동기화로 취소되지 않는다. 메모는 거래 ID가 아니라 안정적인 투자 건 identity에 연결한다.
- 메모: 진입 이유, 무효화/손절 조건, 추가매수 조건, 전략 태그, 복기. 자동 기록 영역과 분리한다.
- 당시 저장한 분석/뉴스/공시의 로컬 링크를 연결할 수 있다. 나중에 재계산한 분석은 `사후 재계산`으로 표시한다. 자동으로 과거 당시 분석을 만들지 않는다.
- 실현손익 대시보드·성과 채점·실시간 알림은 이번 범위에서 제외한다. 수수료·세금은 source가 확인해 주는 항목만 표시한다.

## 인증과 장애

공식 토큰은 24시간 유효하고 만료 전 재발급 금지를 안내한다. 개인용 파일 권한으로 토큰을 보관하고 AppKey·환경별 cache를 분리한다. 병렬 실행의 중복 발급을 막고 만료/오류 재발급 루프를 만들지 않는다. API endpoint는 고정 NH HTTPS 주소만 사용한다. HTTP/업무 오류 및 잘못된 schema는 sanitized exception으로 표면화한다. 선택 항목인 cts/cts_flag가 모두 없으면 terminal로 처리한다. 연속 flag Y에서 키 누락·반복, flag 없이 키만 존재하는 모순은 중단한다.

## 검증과 완료 기준

공식 raw 예제를 출처와 함께 tests/fixtures/nhplug에 보존하고 tests/harness의 boundary contract를 fixture 로딩 시 적용한다. 이 fixture는 실계좌 관찰이 아님을 명시한다. 인증 재사용·페이지 누락·업무 오류·현금/신용 혼재·정수 절삭 방지·누적 체결 갱신·메모 보존·재진입/불완전 이력·CLI end-to-end를 검증한다. 기존 brief/position/notebook 회귀를 실행한다. 실제 계좌 read-back은 별도의 검증 상태로 보고하며 개인 응답을 repo fixture로 저장하지 않는다.
