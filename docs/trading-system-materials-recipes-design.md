# 단계형 모멘텀 매매 시스템 — 재료·레시피·상태 3층 설계 노트

> 이 문서는 독립 리뷰를 위해 자기완결형으로 작성되었다. 리뷰어는 이 프로젝트의 코드나 이전 논의를 모른다고 가정한다.

## 0. 한 줄 요약

주식(한국/미국) 매매 시스템을 만들려 한다. 지금 단계의 결정은 **"룰을 더 만들지 말고, 어떤 룰이 실제로 돈이 되는지 데이터로 골라내는 실험을 먼저 한다"**이다. 이를 위해 시스템을 **재료(Features) → 레시피(Strategy) → 상태(State)** 3층으로 분해하고, 백테스트의 대상을 "레시피"로 명확히 한다.

## 1. 배경과 관점 전환

### 1.1 문제
초기 설계(내부 명칭 v0.4/v0.5)는 상태 기계(state machine) 기반으로 Regime → Trigger → Location → Risk 순서의 매매 로직을 정의했다. 문제는 룰이 계속 늘어나는데(20D 돌파, SMA50 회복, Deep Recovery, Trend Continuation, Pullback 등) **그중 무엇이 실제로 유효한지 데이터로 검증된 적이 없다**는 점이다.

### 1.2 관점 전환
"v0.5 룰을 어떻게 개선할까"가 아니라 다음으로 바꾼다:

> 미네르비니·오닐·와인스타인 등이 반복적으로 강조한 원칙들을 정량화하고, 실제 시장 데이터에서 어떤 조합이 가장 강한 forward outcome을 내는지 찾는다.

대가들의 방법론은 **검증된 정답이 아니라, 탐색 공간을 줄여주는 강한 사전지식(prior)**으로 쓴다. "대가가 썼으니 정답"이 아니라 "대가가 반복 관찰한 것 → 우선 시험할 가설"이다.

참고 문헌(모멘텀/추세추종의 배경 근거):
- A Century of Evidence on Trend-Following Investing — AQR
- Time Series Momentum — Journal of Financial Economics
- Momentum Crashes — Journal of Financial Economics

주의: 위 논문들은 **분산된 시계열 모멘텀**(지수/자산 레벨) 근거이며, 미네르비니·오닐식 **집중 개별주 돌파 + 타이트 스탑**과는 결이 다르다. "모멘텀 팩터가 존재한다"는 배경은 지지하지만 구체적 차트패턴 진입을 직접 검증해주지는 않는다.

## 2. 핵심 관점: 재료 / 레시피 / 상태 3층

세 개념은 같은 줄이 아니라 층위가 다르다. **가르는 기준은 "메모리(과거 기억)가 필요한가"이다.**

- **재료·레시피 = 메모리 없음.** 오늘 차트만 있으면 매일 새로 계산된다.
- **상태 = 메모리 있음.** "언제부터 지켜봤는지, 얼마에 샀는지, 지금 얼마 벌었는지"를 기억해야 나온다.

```text
[재료]   오늘 차트에서 계산되는 객관적 사실           (메모리 없음)
   ↓
[레시피] 재료를 골라·조합해 판단
         "살 자격 있나? 얼마나 강한가? 손절 어디?"    (메모리 없음)
   ↓
[상태]   그 판단 + 내 보유현황으로 갱신되는 진행상황    (메모리 있음)
   ↓
[행동]   관망 / 진입 / 추가 / 축소 / 청산
```

함의: 흔히 "상태"로 착각하는 Regime/Stage는 매일 재계산되므로 **상태가 아니라 재료**다. 진짜 상태는 오늘 차트만으론 못 만드는 것(관심 이력, 보유 현황)뿐이다.

## 3. 재료 (Features) — 메모리 없음, 매일 재계산

전략과 무관하게 누가 계산해도 같은 값. 두 종류로 나눈다.

### 3.1 순수 재료 (가정 없음)
SMA, ATR, 거래량, 고가/저가, 수익률, 신고가 거리 등. 계산에 자의적 가정이 거의 없다.

### 3.2 복합 재료 (가정이 이미 반죽됨)
"재료처럼 보이지만 안에 작은 레시피가 들어간" 것들. 예: VCP는 "T1>T2>T3, 각 수축 몇 %" 같은 가정이 들어간 순간 순수 사실이 아니다. 따라서 **복합 재료의 내부 숫자도 조절 가능한 손잡이(parameter)로 열어두고 함께 시험**해야 한다. 안 그러면 검증한다면서 우리 가정을 몰래 정답으로 깐다.

### 3.3 재료를 관문 순서로 정리 (기존 4층 구조를 수정한 버전)

초안은 REGIME / SETUP / TRIGGER / QUALITY 4층이었으나, (a) SETUP과 TRIGGER가 이름이 겹치고, (b) QUALITY가 독립 층이 아니라 다른 층에 붙는 속성이며, (c) 시장 방향과 위치/위험이 빠져 있었다. 수정본:

```text
0. MARKET      전체 시장이 살 만한 국면인가              (관문)
1. STAGE       이 종목이 상승 단계(Stage 2)인가          (관문)
                 └ 속성: Relative Strength (강한 종목인가)
2. SETUP       베이스/눌림 패턴이 만들어졌나              (무엇을 기다리나)
                 ├ VCP / Cup-with-handle / Flat Base / Double Bottom / Tight Consolidation
                 └ 속성: Tightness (얼마나 조여졌나)
3. TRIGGER     매수 지점이 터졌나                        (진입 사건)
                 ├ Breakout / Reclaim / Continuation  (터지는 "방식"으로만 분류)
                 └ 속성: Volume Expansion, Demand (진짜 터진 게 맞나)
4. LOCATION    너무 뻗지 않았나 / 손절은 어디             (진입 자격 + 사이징)
                 └ 속성: Price near High (위치)
```

핵심 수정 3가지:
- TRIGGER는 setup 이름을 복사하지 않고 **터지는 방식(Breakout/Reclaim/Continuation)**으로만 나눈다. 트리거는 "그 setup이 터지는 사건"이라 setup에 종속된다.
- QUALITY를 층에서 없애고 각 재료의 **속성(점수 눈금)**으로 재배치한다.
- 맨 위 MARKET과 맨 아래 LOCATION/RISK를 되살린다. (Momentum Crashes의 교훈: 시장 방향이 최상위 관문)

## 4. 레시피 (Strategy) — 재료를 조합해 판단, 메모리 없음

대가의 "전략"이란 같은 재료 창고에서 **무엇을 골라, 관문으로 둘지 점수로 둘지, 얼마 비중으로, 어디서 자를지**의 조합이다.

```text
레시피 = 선택          어떤 재료를 쓸지
       + 관문/점수     필수 통과(gate) vs 가점(score)
       + 비중/문턱값   얼마나 무겁게, 어느 값부터 인정
       + 매도·사이징   청산과 비중조절 규칙 (레시피의 일부)
```

- 미네르비니 = 레시피 A (VCP 조임 + 정확한 pivot을 무겁게)
- 오닐 = 레시피 B (EPS 성장 + RS + 기관 수급을 무겁게)
- 우리 후보 = 레시피 C, D, E …

레시피의 출력은 하나로 수렴한다: **"이 종목, 지금 살 자격 있나? 얼마나 강한가? 손절은 어디?"** 이 출력이 다음 층(상태)을 움직인다.

중요: 레시피는 "비중 평균"만이 아니다. 대가 전략은 대부분 **필수 관문(gate)이 먼저, 그다음 점수(score)**다("Stage 2 아니면 무조건 탈락" 같은). 가중평균만으로는 이 구조를 표현할 수 없다.

## 5. 상태 (State) — 메모리 있음, 거래 생애주기

레시피 판단 + 내 보유현황이 만나 갱신된다. 미보유 쪽과 보유 쪽으로 갈린다.

```text
미보유 (관심의 상태)   WatchState
  IGNORE → WATCH → ARMED → ENTRY_CANDIDATE
  (관심 없음 → 지켜봄 → 준비됨 → 진입 후보)

보유 (재고의 상태)     PositionState
  FLAT → PROBE → CORE → FULL
  (없음 → 소량 탐색 → 핵심 → 최대)

보유 관리 모드         ManagementMode : NORMAL / WINNER
축소 단계             RiskLevel : 0 → 4  (목표 노출 100/85/65/35/0%)
```

레시피가 "자격 있음 + 강함"을 내면 WatchState가 ENTRY_CANDIDATE로 올라가고, 실제 진입하면 PositionState가 PROBE로 넘어간다. 많이 벌면 WINNER로 승격, 무너지기 시작하면 RiskLevel을 올려 단계적으로 축소한다.

WatchState와 PositionState를 나누는 이유: 답하는 질문이 다르다(관심 vs 재고), 붙는 데이터가 다르다(후보일자/쿨다운/랭크 vs 진입가/손절/수량/손익/episode_id), 만드는 모듈이 다르다(스캐너/워치리스트 vs 포지션 관리).

## 6. 실험(백테스트) 접근

### 6.1 백테스트의 대상 = 레시피
재료 층은 고정해두고 **레시피만 갈아끼우며** forward outcome을 비교한다. 즉 "20일 돌파가 좋은가"를 고립해서 묻는 게 아니라 "이 재료들을 이렇게 조합한 레시피가 저 레시피보다 나은가"를 묻는다.

### 6.2 가드레일 (없으면 실험 자체가 착각 생성기가 됨)

1. **다중검정/과적합 통제.** 여러 레시피를 같은 데이터에 돌리면 일부는 우연히 좋아 보인다. 대응: 최종 채택 직전까지 잠가두는 **홀드아웃 구간**, 시험한 변형 수 기록 + Deflated Sharpe 등 **다중검정 보정**, **walk-forward**.
2. **평가 라벨을 목표와 일치.** "가격이 올랐나"가 아니라 스탑·익절 포함 실제 거래의 **R(손익/위험) 분포**로 잰다. 목표가 "작게 잃고 크게 먹기"라서다.
3. **트리거와 청산은 분리 최적화 불가.** 트리거 선별 단계에서는 **고정된 기본 청산**(예: ATR 스탑 + SMA 이탈)을 공통으로 깔고 같은 조건에서 비교한 뒤, 이후 공동으로 미세조정.
4. **생존편향 제거.** 상장폐지 종목 포함 **시점정합(point-in-time) 유니버스**. 특히 미국 돌파 전략에서 이걸 안 하면 실제보다 훨씬 좋아 보인다.
5. **국면 조건부 성과.** Momentum Crashes 교훈. 평균 엣지는 착시일 수 있으므로 강세/약세·고변동/저변동 국면별로 성과를 쪼개 본다.
6. **거래비용/슬리피지/갭 반영.** 돌파 진입은 슬리피지가 크다. 처음부터 넣는다.
7. **희귀 패턴 통계 주의.** VCP·컵핸들은 사례가 적어 신뢰구간이 넓다. 통계가 탄탄한 단순 룰(20D 돌파, SMA50 회복)로 harness를 먼저 검증하고 확장한다.

### 6.3 실행 순서

```text
0. 가드레일 확정 (실험 전 필수)
   - forward-outcome 라벨 = R 분포로 못박기
   - 시점정합·상폐포함 유니버스, 거래비용 포함
   - 홀드아웃 잠금 + 시도 수 기록
   - 트리거 선별용 고정 기본 청산 지정
1. 소수의 고표본 트리거(20D 돌파 / SMA50 회복 / 타이트 pullback)로
   harness 자체가 정직한지 검증
2. 검증된 harness 위에서만 VCP·컵핸들 등 희귀 패턴 확장
3. 트리거 선별 → PROBE/BUY/ADD → WINNER/EXIT 순으로 다듬기 (국면 조건부 리포트)
```

## 7. 아키텍처 매핑

기존 시스템(stateless 스냅샷 조언)은 건드리지 않고, 데이터·지표 계층만 공유하는 별도 엔진을 세운다.

```text
Shared Primitives (재료 층)
  providers(OHLCV/펀더멘털) + look-ahead-free 지표/피봇 + MarketProfile(KR/US)
        │
        ├──> 기존 Snapshot Advice (그대로 둠)
        │
        └──> Trading Research Engine (레시피 + 상태)
                  regime→setup→trigger→location  +  watch/position state
                        │
                        └──> Backtest harness (레시피 검증)
                                    │ (검증 통과분만, 표시 우선)
                                    └──> Report / CLI / 기존 조언에 evidence로 연결
```

- 엔진은 순수 결정 함수 + day-stepper로 유지. 입력 "t까지의 봉", 출력 "t+1 집행안". I/O는 밖에서 주입 → 백테스트와 실운영이 같은 엔진 공유.
- 재료 층은 골든 테스트로 고정(여기가 틀리면 위가 다 오염).

## 8. 열린 결정들 (리뷰어 의견 요망)

1. **forward-outcome 측정 방식.**
   - A: "신호 후 N일 수익률 > X%" (단순, 그러나 비대칭 목표와 어긋남)
   - B: 고정 기본 청산 포함 미니 거래 시뮬 → R 분포 (목표 일치, harness가 무거워짐)
   - 현재 기울기: B.
2. **상태 저장 방식.** 로컬 보유 파일 확장(단순) vs 별도 상태 스토어/SQLite(이력·episode 추적 유리).
3. **Regime 분류.** 기존 WEAK/TRANSITION/TREND/BROKEN 유지 vs Weinstein Stage 1~4로 교체 — 어느 쪽이 더 나은 분류인지도 실험 대상으로 둘지.
4. **복합 재료의 파라미터화 범위.** 어디까지 손잡이를 열지(열수록 과적합 위험↑, 적을수록 대가 원칙과 괴리↑).

## 9. 주의·한계

- "대가가 검증했다 ≠ 수익이 보장된다." 방법론은 강한 가설을 줄 뿐, 최종 채택은 우리 표본·기간·거래비용·시장별 데이터로 확인한다. 미네르비니 측도 과거 성과가 미래를 보장하지 않는다고 명시한다.
- 학술 근거(TSMOM)와 우리가 하려는 개별주 돌파는 범위가 다르다(§1.2).
- 이 문서는 "무엇을 만들지"가 아니라 "무엇을 어떤 순서로 검증할지"의 설계다. 룰 확정이 아니라 실험 설계가 산출물이다.
